SECCIÓN H — CONSISTENCIA DE LOS DATOS Y LIMITACIONES ADICIONALES
==============================================================================

── H.1 — Filas corruptas en descargas_final.csv ──────────────────────────────
7 filas del archivo tienen comas sin comillar dentro de 'mensaje_error' (ej. 'Contenido inválido: 8,872 bytes, inicio=ffd8ffe0'), lo que rompe el parser por defecto de pandas/Stata/R. Las 7 filas corresponden todas a descargas fallidas (exito=False) y no afectan ninguna imagen usada en los embeddings, pero el archivo debería regenerarse con comillado CSV correcto para evitar que un análisis futuro las descarte en silencio o falle al leer el archivo.

── H.2 — Mensajes de error también muestran mojibake de codificación ─────────
El texto de mensaje_error contiene secuencias como 'invÃ¡lido' en vez de 'inválido', indicando una doble codificación UTF-8/Latin-1 en algún punto del pipeline de descarga o de guardado del CSV. No afecta variables numéricas, pero conviene corregirlo si el texto de error se usa para clasificar fallos.

── H.3 — Identificador 'llave' faltante en algunas filas de ola 2016 ─────────
304 de 6659 filas de ola 2016 (4.6%) no tienen 'llave' (identificador de panel 2013) a pesar de no ser ola 2010. Puede deberse a sub-hogares 2016 sin contraparte directa en 2013 (nuevas divisiones); se documenta para que la unión con el panel ELCA lo tenga en cuenta y no se asuma como error de construcción sin verificar antes con las tablas ELCA.

── H.4 — Radios de búsqueda: código actual vs. reportes previos ──────────────
consultas_final.csv usa los radios [50, 100, 200, 500] metros. El código actual de 01_analisis_cobertura_gsv.py (CONFIG['radios_m']) usa [50, 100, 200, 400], y el reporte de texto reporte_cobertura_gsv.txt (de una corrida anterior) documenta [50, 100, 200, 500]. Los tres no coinciden entre sí. Esto confirma que los reportes .txt existentes en data/processed/embeddings/ no reflejan ni el código actual ni los datos finales entregados, y no deberían citarse como fuente en la tesis: la fuente autoritativa es consultas_final.csv / descargas_final.csv.

── H.5 — Carpeta de datos mixta con un pipeline no relacionado ───────────────
data/processed/embeddings/ contiene, además de los archivos de Street View, reportes de un pipeline distinto basado en imágenes satelitales Sentinel-1 (reporte_coleccion_s1.txt, reporte_composiciones_temporales.txt, reporte_conexion_gee.txt, reporte_extraccion_buffer.txt, reporte_metricas_textura.txt). Quedan fuera del alcance de este análisis, que se limita a Google Street View, pero conviene separarlos en carpetas distintas para evitar confusión sobre qué reporte corresponde a qué fuente de datos.

── H.6 — 'uuid.py' local sombrea la librería estándar ────────────────────────
El script uuid.py que el estudiante dejó en esta misma carpeta (usado para generar photo_id_uuid al anonimizar) tiene el mismo nombre que el módulo estándar de Python 'uuid'. Python antepone el directorio del script en ejecución a sys.path, así que cualquier código —incluyendo matplotlib, que depende de 'uuid' internamente— que se ejecute desde esta carpeta importará ese archivo en vez de la librería estándar y fallará. Este mismo script tuvo que neutralizarlo explícitamente para poder generar las figuras. Se recomienda renombrar uuid.py (p. ej. a anonimizar_photo_id.py) antes de que rompa otro script del pipeline.
